# 漫画矢量重绘与分色

适用于“漫画描边、平涂、大色块、类似 Logo、干净 SVG”等图片重绘需求。目标是保留主体辨识度，用少量平滑曲线和有限纯色重建图形。需要助手具备看图、编写文件和本地渲染能力；曲线由助手根据图像结构编写，Bigchx 提供颜色分析、分色参考与后续打印计算。

## 确定本次交付

- 沿用用户选择的形象、风格、色数和背景。用户只要看效果时，完成 SVG 与 PNG 即可，无需打印参数。
- 用户让你设计分色方案且没有指定色数时，可以根据主体提出一版有限色试稿，说明选了几色；不要把某次试稿的 7 色、尺寸或线宽作为所有图片的默认值。
- 保留已有 Logo、文字和人物特征；用户只要普通分色或精确描摹时，不要自动改成漫画风。艺术重绘与逐像素还原是不同目标。

## 原图分析与分色参考

1. 使用 `analyze` 统计完整原图。输出中的主色组百分比以整图为分母；不要用重绘面积冒充原图统计。
2. 用户要求“先分色再重画”时，实际运行 `separate`。二维参考可用 `detail`，按图像颗粒选择少量模糊、平滑和孤立像素清理；有准确 HEX 时锁色。展示真实 `preview.png`。
3. 将细碎灰阶归并成主体色、轮廓色和必要点缀色。白色高光、眼白与白色背景可能共用色值，去背景时依据区域和透明度保留内部白色。

## 按主体结构重画

先看整体剪影、关键比例、表情和前后遮挡，再分解为有意义的部件，例如后发、脸、五官、刘海和前景装饰。使用有名称的 `<g>` 分组，后方形状先画，前方形状后画；避免在本应连成一体的位置留下细缝。

- **轮廓重绘**：用闭合贝塞尔路径描述填充区域。节点集中在转折和曲率变化处，平滑连接处保持切线连续；不要沿每个颗粒或像素拐点堆积节点。
- **平涂分色**：将颜色集中为一组明确的 `#RRGGBB` 色值，轮廓色也计入色数。小面积颜色是否保留取决于辨识度和目标色数。透明不计为耗材颜色。
- **描边规范化**：使用一致的外描边与较细内线，设置 `stroke-linecap="round"` 和 `stroke-linejoin="round"`。例如约 800 单位画布可从外线 8–12、内线 5–8 单位试起，再按造型调整；这是视觉起点，不是打印线宽保证。
- **形状简化**：清除颗粒、杂点、过小锯齿，保留眼睛朝向、嘴形、配件与主要色块的位置。无需机械复制原图全部细节，也不要擅自添加会改变表情的新特征。

使用自包含 SVG：设置 `viewBox`，显式声明纯色 fill/stroke；默认输出透明背景的艺术源文件，预览可另铺白底。交付可编辑路径，不在 `<image>` 中嵌入原图，不使用渐变、纹理或滤镜模拟平涂。需要文字时保留准确字形并转为路径，避免依赖用户设备字体。

## 渲染、复查与交付

技能提供一个辅助命令，将助手已写好的平涂 SVG 渲染为图片：

```sh
node scripts/render-svg.mjs --input job/artwork.svg --out job/vector --size 1600
```

它**不执行照片自动描摹或 AI 绘图**，只渲染并检查适合此流程的 SVG 子集。只用于当前任务创建、可检查的本地 SVG。支持 svg/g/path/rect/circle/ellipse/line/polyline/polygon/title/desc/metadata；颜色使用显式六位 HEX 或 none，继承填色应明确写在 svg/g 上。CSS、渐变、外部引用、位图、文字和透明叠色需先整理成纯色路径。脚本使用技能已有的 sharp，无新增运行依赖。

输出：

- `artwork.svg`：保留可编辑源文件和画布。
- `transparent.png`：保留源图 alpha；透明源图的背景保持透明。
- `preview.png`：仅供观看的白底预览，**不要用它制作去背景模型**。
- `subject-print.png`：按 alpha≥128 的主体包围盒裁剪的二值透明 PNG，供后续分色；内部白色保留，颜色边缘仍有抗锯齿。
- `palette.json`：SVG 声明的唯一 HEX 清单，可能包含被完全遮挡的颜色，并非像素统计或实际非空耗材数。
- `render.json`：渲染尺寸、裁剪框、颜色数和是否存在透明像素。

生成后实际打开 PNG，至少检查大图和缩略图：整体比例、曲线接头、描边粗细、遮挡、孔洞与关键表情是否合理，边缘有没有裁断。使用渲染结果迭代路径。检查 SVG 无嵌入位图、填色符合预算。若输出意外不透明，先检查是否画了全画布背景矩形；脚本不会把所有白色自动删除。

先展示最终 PNG，再交付 SVG；需要比较时提供“原图 / 技能分色 / 矢量重绘”对比图，明确三者来源。说明重绘经过了哪些简化，避免称为像素级无损还原。不要把用户图片或重绘作品加入分发技能包、公开展示页。

## 从重绘 SVG 衔接打印

用户继续要求打印时，已完成的重绘作品就是新的输入源。保留艺术 SVG，读取 [打印参数](printing.md) 和 [本地命令](local-cli.md)：

1. 使用 `subject-print.png`，按最终尺寸、实际机型/喷嘴和厚度运行 `printable` / bigchx-K。以主体包围盒控制成品宽高，透明画布边距不应计入用户要求的最长边。普通分色仍以原图为输入；此处输入改变来自用户授权的重绘任务。
2. 将有意义的颜色锁定后重算轮廓，不能把屏幕上平滑的 SVG 直接当作已验证打印几何。线条近似物理宽度为 `SVG 线宽 ÷ 主体在 SVG 中的跨度 × 成品对应边长 mm`；最终仍以分色结果和切片走线为准。
3. 根据 `layers.json` 的实际图层编号分配目录中存在的官方耗材组件 ID，不要假定图层顺序等于 palette.json 顺序。保持黑色、双粉等语义和色块对比；数学上最近的颜色若偏离用途，可选更合适的官方色并解释取舍。
4. 换色后展示实际生成的 `preview.png`。检查色层非空、白色仅在需要的位置、透明孔洞未填回，以及整体连接性；用户要求一体标牌时，不应留下没有连接的独立部件。
5. 按最终机型导出 3MF。确认平台范围、材料/喷嘴预设、厚度及网格有效性。可用切片器时进行本地切片检查，只有确实成功才说“已切片验证”。艺术 SVG 的路径仍保留；3MF 中是重采样后按物理线宽清理的几何。

色数与设备自动换料能力分别处理。例如常规 A1 + AMS lite 同时自动管理 4 色，用户坚持 7 色时保留七层，但应明确需要额外手动换料方案。七色工程或切片成功不等于 A1 七色自动打印可用；未配置换料暂停时明确说明，不把普通七色 G-code 当作可直接运行的手动换料文件。

## 示例请求

> 使用 $bigchx-make，先分析和分色，再把图片重绘成漫画描边风格。保留主体特征，用平滑曲线、统一粗描边和有限纯色色块，输出透明背景 SVG，并给我看 PNG 预览。

用户确认效果并继续要求打印时，沿用已确认的图稿，补齐会影响打印的参数，再匹配耗材并生成工程，不反复询问已给出的选择。
